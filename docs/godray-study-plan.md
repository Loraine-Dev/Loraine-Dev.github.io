# 首页阶段一至三 · 云谷体积光最小原型计划

用户本轮只授权先审查、选择一个升级并打开验收。完整官网必须等待首页确认；不部署。

基线 fda8eac。上一轮统一叶冠/倒影受光收益有限，不将它视为被认可方向。已认可的是世界树主画和基础云带。

## 选择

审查：桌面品牌左/树右；手机树上/品牌下。暗门、岸、遗迹、云谷层次清楚；暖光后方缺少穿过蓝色空气的可读光路。最强是门后世界的向往感，弱项是局部高光无法建立体积。

比较 A 少量被地形遮挡的云谷散射光、B 镜头构图接力、C 水面反射微扰后，选择 A。它有机会同时改善源光逻辑、空气、云雾与空间。B 需重校构图且已有视差；C 的合成水面缺少流向，边际收益低。三者不同时实施。

## 执行顺序

1. 先写 DEV 原型验收的失败测试：新光路可启闭；云带节点/相位不重建；关闭新光路仍有云；暂停、后台、减少动态、响应式、无 WebGL、生产默认不受影响。
2. 集中 JSON 定义桌面/手机光源、方向、软角宽、径向衰减、地形遮挡与两种微小分布。用确定性技术生成器烘焙两个散射 alpha 场。保留源参数、哈希与裁切边界；不重画主视觉。
3. 只在 `?artStudy=godrays` 开启。云带/原镜头不变；候选里暂停并隐藏未被认可的独立树光/水光，改为两张局部光路缓慢交替。没有连续 Canvas/WebGL 体积运算，没有粒子或新几何。
4. 先在真实浏览器看截图/原速录像，检查源点、岩壁遮挡、柔软度与是否像白色贴片。若破坏美术则调整选中方案，不增加其他候选。
5. 固定桌面与手机视口录制开/关真实 A/B，云始终原速运行；首段不输入，后段同输入验证原视差。执行构建及实际行为测试，记录性能边界。
6. 保存本地提交和回滚，打开原型供用户验收。未经确认不制作内页、不发布。
