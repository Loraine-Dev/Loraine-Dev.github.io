# 首页静止故障修复 · 2026-10-20

本轮仅修改首页环境动画启动、幅度与本地诊断。没有替换主视觉、修改其他页面、增加新特效或部署。用户视觉验收仍待完成。

## 根本原因

1. `mobileStart: "interaction"` 导致手机和满足竖幅条件的窄桌面窗口，在首次输入前根本不创建环境模块。无输入 30 秒对照的时间轴数与像素差均为零。
2. 宽桌面已创建四模块、八条 WAAPI 时间轴，但银白叶冠上再叠极弱银白光，且雾幅度和透明度过低。时间轴在走不等于人眼能辨别：旧版采样全画面最大通道差仅 9/255，超过 8 的通道数最多 70。
3. 瀑布一直是远景绘景内的静态素材，并不存在一个失效的独立瀑布动画。

本次复现中没有 JS 异常、资源失败、遮罩缺失或前景静态图误覆盖。页面 visible、IntersectionObserver 可见、reduced-motion 未触发，WAAPI 未被 CSS 暂停。没有 GSAP 环境时间轴；Three 镜头按需绘制，闲置帧数不增长是设计行为。没有证据证明用户原标签加载了旧缓存，因此不将缓存认定为根因。

## 实际修复

- 手机环境改为 `auto`，不等滚动；低内存、节省流量、减少动态与后台/离屏暂停继续有效。空间镜头仍按需初始化。
- 保留两层局部遮罩雾纹理，仅校准位移、透明度和相位。不是移动整幅远景。
- 叶冠亮度遮罩内改为轻柔冷色局部阴影，随透明度缓慢起伏；树干、轮廓和背景像素位置不变。
- 水面局部反射维持极弱变化；没有强行制作瀑布流动。
- 开关单项效果时保留其他模块相位，避免调试产生无关跳变。

集中参数：`src/data/environment.json`。远雾单程 60 秒、水平 4.5%；中雾单程 46 秒、水平 -6%；采用交替缓动而非硬重置。树光 22 秒周期、最大 opacity 0.18，手机强度 0.85；数值还乘素材和遮罩 alpha，并非全画面曝光。颜色在 `src/styles/site.css` 的 `.treeLight`。遮罩定义仍在 `art-source/world-tree/motion-regions.json`，运行时使用预生成 WebP；不存在运行时 JSON 请求失败。位移范围是局部纹理坐标，不是全图平移百分比。

## 证据与复测

`artifacts/idle-motion/{before,after,off}/report.json` 与同目录截图记录桌面 1440×900、手机 390×844 的 0/5/15/30 秒无输入测试。两个视口都没有滚动、鼠标或触摸；所有采样 scrollY=0。视频是同次真实 Chromium 正常速度录制，不是静态图插帧，也没有调快时间轴。

| 对照     | 桌面最大通道差 / 差值≥8通道数 | 手机最大通道差 / 差值≥8通道数 |
| -------- | ----------------------------- | ----------------------------- |
| 修复前   | 9 / 70                        | 0 / 0                         |
| 修复后   | 22 / 17499                    | 23 / 5130                     |
| 关闭环境 | 0 / 0                         | 0 / 0                         |

数值为各采样相对 0 秒的最大值，通道数不等于像素数。修复后远雾、树光各自区域也达到像素信号门槛。区域可能交叠，不能据此归因每个单独像素；独立开关另由浏览器测试覆盖。这证明启动与像素变化，不能代替用户判断“自然且肉眼可见”。

MP4 为原始 WebM 最后 30 秒的正常速兼容转码：`desktop-normal-30s.mp4`、`mobile-normal-30s.mp4`。`off-on-30s.mp4` 左关右开，仅并排合成，未加速。完整 WebM、原图及 JSON 仍保留。30 秒采样没有发现瞬时跳变或资源异常；这不是覆盖所有相位的长时间人工审美证明。

## 素材限制与回滚

现有门体/近岸为独立透明层，远景内的树、建筑、瀑布仍合成。可靠瀑布运动最低需要独立水体 alpha、流向或连续序列、岩壁遮挡以及无水底图。本轮没有剪移原图制造空洞、重影。
