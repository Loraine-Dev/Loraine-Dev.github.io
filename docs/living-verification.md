## 性能测量

最终本地 Lighthouse 移动模拟：**83 / 100 / 100**（Performance / Accessibility / Best Practices），FCP 1.1 秒、LCP 3.4 秒、TBT 370 毫秒、CLS 0。证据 `verification/lighthouse-release.report.html`、JSON。运行条件：生产预览、Windows、无头 Chromium、模拟移动网络/CPU、软件 WebGL；本次复测未并行启动录屏或自动化浏览器测试。

此前开发检查曾出现 51–86 的分数，包含不同代码阶段和并行录制负载；不将其作为当前成绩，也不沿用上一艺术原型的 92 分。83 仍有优化空间，不能宣称所有设备 60 fps 或无成本。

环境图层使用预烘焙纹理与 Transform／Opacity，不运行逐帧 JS、实时噪声或连续 WebGL。合成矩形总面积由四个全图减少约 91%（桌面）/93%（手机）；这是几何面积估算，不等同于 GPU 时间改善比例。手机首帧静态，首个探索/滚动手势才激活动画与镜头；低内存、节省流量保留静态。

## 动态证据与检查方法

桌面 `desktop-real-time.webm` 为浏览器原始录制：192 秒环境真实时间，再进行原生滚动前进和返回；MP4 为兼容转码，没有加速或静态图拼接。192 秒覆盖最慢雾层完整往返以及其余各层至少一个周期。手机录制先真实输入激活动态，保留初始视角运行 30 秒，再触控探索。

实际采样帧 0、10、20、30、60、96、155、192 秒与录制状态保存在 verification/。观察 30 秒帧及相邻时间，未发现明显重复接缝、重影、原图露底或主体边缘断裂。运动本身刻意很弱；放大 16 倍的帧差图仅用于定位变化区域，不能当作正常视觉效果。循环使用往返缓动与首尾同值透明度；各层时长错开，没有短的全场同步循环。

录制脚本同时检查静置期间 WebGL 计数不变，结果和浏览器主线程计数在 `recording-report.json`。主线程计数不包括 GPU 耗电；录屏会引入捕获/编码开销，不能将视频帧率视作网站实际帧率。

最终 192 秒录制中 WebGL 计数固定为 3；主线程任务累计 275.225 毫秒，ScriptDuration 与 LayoutDuration 增量均为 0。10 秒/30 秒实际帧差平均每颜色通道约 0.110/255，最大 7/255，变化局限于叶冠、雾区等局部。它说明动态存在且克制，不代表美术自动合格。MP4 已做实际帧解码检查。

## 已知限制

没有实体手机、Safari、真实低端 GPU 的持续帧率或功耗测试。两层雾是局部附加散射层，不是完整分离的云海；水面只有局部反射光变化，瀑布和波面位移静态。树、建筑仍在同一绘景，不支持自由环绕。技术检查通过不等于用户美术验收通过。
