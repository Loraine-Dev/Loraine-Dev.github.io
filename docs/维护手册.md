# MILOQEN V1.0 中文维护与发布手册

当前为 1.0.0-rc.1 待验收候选，不代表已上线。旧手册保留为 维护手册-整合前20261021.md；其中旧光路入口、旧性能数字和回滚点是历史记录，当前以本手册与交付报告为准。

## 1. 工程与启动

Node.js 24，npm ci 使用锁文件安装。npm run build 执行内容生成、TypeScript 和 Vite 静态构建，结果 dist。终端一 npm run dev 打开 http://127.0.0.1:4176/；终端二 npm run preview -- --port 4177 打开生产构建。Vite、TypeScript 与轻量静态模板沿用原项目，未加入新运行库。

## 2. 内容与组件

|入口|职责|
|---|---|
|src/data/site.json|品牌名称、宣言、GitHub|
|src/data/works.json|作品数组，真实状态、方向、计划平台|
|src/data/editorial.json|首页叙事、理念、关于、日志空状态与联系文案|
|content/journal/*.md|真实创作记录|
|scripts/site/components.mjs|共享导航、页脚、SEO 和非游戏画面的原创图形概念|
|scripts/site/pages.mjs|内页与首页叙事结构|
|src/page.html|首页艺术场景源模板|
|src/styles/tokens.css|共同配色、字体、间距、内容栅格变量|
|src/styles/site.css / editorial.css|场景与编辑页面布局|

增加作品仅追加 works.json 项目。不要把计划平台写成已发行平台，不得虚构开发成果、截图、试玩、团队或法律资质。Contact 目前只有确认的 GitHub；TapTap 需先确认公开厂商 URL，再在 site.json 的 taptap.url 填入地址并将 confirmed 设为 true，模板自动显示；当前 url:null、confirmed:false，不显示占位。不要使用后台地址或猜测网址。

## 3. 发布日志

见 content/journal/README.md。Markdown 文件名决定路由。JSON front matter 包含 title、summary、真实有效 date 和 published:true；草稿 published:false 不输出。支持安全的有限 Markdown，HTML 转义，不执行嵌入脚本。当前没有真实公开文章，保持空状态。

scripts/render.mjs 同步生成六页、文章页、SEO、sitemap、robots 和 404。index.html 与内页 index.html 是生成物；不要直接编辑。生成路由清单 .generated-journal.json 需入 Git，撤稿时只清理清单内旧文章生成文件，不递归删除其他目录。

## 4. 动态与素材

主景 world-desktop.webp / world-mobile.webp 保持原图。原画、提示与来源记录位于 art-source/world-tree；任何换图必须重新校准手机裁切、水域边界、光源、地形与遮罩，不能套用旧区域。

- 云雾：src/data/environment.json、environment-regions.json、src/scenes/environment.ts。沿用原两层动态。
- 局部水面/树冠/光路：src/data/living-scene.json、src/scenes/living-scene.ts。仅首页加载，2D 纹理处理，无新 3D 几何。
- 光路姿态来源：src/data/godray-assets.json 与 public/art/world-tree/godrays。旧 mountGodrays 模块保留作历史，当前不挂载。
- 区域遮罩：npm run assets:living；来源与 SHA 在 art-source/world-tree/living-manifest.json。无损 WebP 与原 PNG 解码逐像素一致，PNG 保留参考。
- 前景优化：npm run assets:optimized；编码、裁切和来源见 optimized-manifest.json；旧 WebP 回退保留。
- 镜头：src/data/world.json、src/scenes/world-scene.ts；场景交互按需绘制，局部材质正常播放上限桌面18次/秒、手机15次/秒；软件WebGL上限6次/秒，保持原采样尺寸，非实测帧率承诺。

水面是限定水域的原纹理重采样，树冠是局部受光变化，光路是带地形遮挡的2.5D近似。没有独立瀑布、枝叶骨骼或天空明暗循环。不能把这些静态部分写成已实现动画。

## 5. 暂停、降级与验收入口

暂停按钮控制云雾、局部材质与镜头。后台、离屏停止新增材质绘制；减少动态、低内存/省流保留静态主图；无 WebGL 仍有原画与 CSS 云雾。新增材质上下文丢失会保持静态该层、不强制刷新；重载页面后重建。

开发原页 /?motionMode=off|all|rays|water|tree|clouds 可隔离各项；生产不接受这组调试开关，不显示诊断面板。/review/living.html 是首页对比，/review/v1.html 是完整生产构建实时验收，/review/v1-gallery.html 是本次截图与导览。review 与 artifacts 不进入 dist。

## 6. 检查与录制

先运行两个服务，再 npm run check。npm run test:browser 覆盖镜头、回退、布局与可用其他浏览器；其他浏览器部分检查使用减少动态，不等于完成所有浏览器GPU动态验收。npm run test:release 检查静态路径与部署文件。npm run verify:art 是编码辅助检查，不代替艺术判断。

node scripts/quality-audit.mjs v1 3 运行当前生产构建三轮移动模拟 Lighthouse，勿同时运行其他浏览器压力任务。记录每轮，不只取最高分。软件 WebGL、模拟节流和实体手机不同，不能宣称真实用户 p75。

PowerShell 中设置 REVIEW_OUT 为 artifacts/v1 后，node scripts/record-site-tour.mjs 录制本次完整站点导览；node scripts/review-living-scene.mjs 录制静置30秒与六项对比。录像正常速度，不使用调试加速替代验收。

## 7. 正式发布（须另获明确批准）

1. 确认待发布提交和验收记录，记录当前线上部署SHA以便恢复。检查远端已有工作流，避免旧push流程在提交时自动发布。
2. 有权限的人将批准代码经PR合入发布分支。当前未推送、未创建PR，也未重新测试GitHub写入权限；不声称本轮遇到403。如权限不足，使用交付源码/静态包继续操作。
3. 仓库Settings → Pages选择GitHub Actions。Actions手动运行 Publish reviewed website，输入 MILOQEN-PUBLISH。工作流使用npm ci、构建与部署包完整性检查，上传dist。
4. 等待build/deploy成功，访问正式域名、六页直达、随机不存在路径、手机菜单与GitHub链接，检查静态回退和资源。

工作流尚未在远端执行验证。本项目使用GitHub用户根站点；dist中的index.html、assets、art、images、sitemap、robots和.nojekyll直接位于站点根。若改项目子路径，必须同时改资源、canonical、sitemap与404根链接。不要仅上传源码ZIP附件就声称已部署。

## 8. 回滚与版本

本轮开发分支 codex/miloqen-v1-integration；整合前回滚 codex/stable-before-v1-integration-20261021 指向 de168d2。此前525d4f4、f4f6f8e及稳定分支保留。不要用强制reset覆盖工作文件。

发布前查看旧版使用独立检出或解压备份。上线后通过revert实际合入的发布提交，再手动运行相同Pages流程；若采用squash应revert实际squash提交。要恢复发布前的正式网站，应部署此前记录的线上SHA，不能假定本地f4f6f8e就是旧线上版本。
