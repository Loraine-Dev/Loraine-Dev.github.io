## 最终采用的改动

1. **主景保持原 WebP**。`world-desktop.webp` 和 `world-mobile.webp` 未修改；世界树、星门构图、中文字标与主标题位置不变。
2. 星门、岸边、云纹理从原始 PNG 导出同尺寸 AVIF，并保留全部原 WebP 回退。没有缩小图片来换取分数。编码选择为前景 quality 70 / 4:4:4、云纹理 quality 75 / 4:4:4；这些数值不是跨格式的质量评分。
3. 增加仅供 `max-aspect-ratio:9/16` 使用的岸边素材：从原参考 1280×720 中央取 406×720，去除窄竖屏中视口外的像素，保持像素比例，不重绘、不改变树与星门裁切。
4. 镜头纹理复用 `<picture>` 实际选择的 `currentSrc`，避免进入 WebGL 后再下载完整 WebP；跨越岸边竖屏裁切边界时重新建立纹理，避免转屏后比例不正确。
5. 关键云纹理与中景遮罩使用明确的高优先级预加载，预加载文件与真正显示的文件一致。系统字体没有网络字体请求，未增加字体文件或阻塞字体加载。
6. 两层云雾的位置、形变、速度、光路和镜头参数保持原样。去掉两条数值始终相同的透明度时间轴，改为相同的固定密度；没有关掉可见动态。环境有效时间轴从 10 条减为 8 条（含两条光路），未增加效果。

## 为什么 LCP 较慢

基线最大的候选是中景云雾遮罩。场景需要主景、透明前景、岸边、云纹理、遮罩和光路多张资源共同构图；原始首屏图片传输约 646 KiB。字体没有外部请求，因此不是网络字体等待问题。云雾还要经过脚本初始化、图片解码、遮罩与合成后才能完整绘制，不能只靠减小一张背景图解决。

预加载发现和最终绘制是不同阶段；[web.dev 的 LCP 分解方法](https://web.dev/articles/optimize-lcp)用于本轮分析。抓取报告中的实测分段与 Lighthouse 模拟后的最终 LCP 不可直接混为同一时间线。

继续压到 2.5 秒，可能需要重新组织首帧合成素材或场景接管方式，并验证云雾遮挡、门框、首帧和交互时的无缝切换。本轮没有用降分辨率、隐藏 LCP 元素、关掉云雾、延迟展示主视觉或降低测试阈值来换分数。

## 被拒绝的实验

- 仅提升请求优先级：单轮 LCP 4.817 s，没有达到目标。
- 将两层云雾初始姿态输出到 HTML 并复用节点：单轮 5.000 s，没有证明收益，结构改动已撤回。
- 全部主景改为 AVIF：三轮 LCP 约 3.61 s，但 Speed Index 中位数约 2.48 s，主景文件仅节省约 22–25 KiB；最终恢复原主景 WebP，选择整体更均衡的混合方案。
- 编码与冷启动实验中曾出现预加载与显示选源不一致；已用真实请求检查修复，最终不重复下载前景 WebP。不能把中间错误配置的结果当成最终结果。
- PNG 遮罩在手机上更大，未采用；所有原遮罩保持不变。
- 纯 WebP 和不同动画内部结构也进行了对照。实验原始数据保留在 `artifacts/final-quality/`，不把失败数据删除或当成正式结果。

## 美术与响应式审查

同视口、同镜头与同动画相位采集 1440×900、768×1024、390×844 前后截图；品牌区、远景、星门和岸边 DOM 框位置与尺寸相同。逐页检查 Home、Works、Philosophy、About、Journal、Contact 的桌面、平板和手机画面，保留原有墨色/纸色、字体层级、留白与导航节奏，没有新增转场特效或装饰。

手机世界树继续位于上方、文字位于下方，未以画面缩小来容纳文字。平板保留原来较近的树冠构图。Works 仍为“策划中 / In Planning”，并明确“策划与研究中，尚未正式进入游戏开发”；计划平台手机与 PC。Journal 仍为真实空状态，Contact 只使用确认的 GitHub。

新编码使用原始 PNG、原尺寸及同一绘画内容。五份资源的局部 8×8 亮度 SSIM（暗底合成）相对源 PNG 不低于旧 WebP，结果由 `npm run verify:art` 重现。SSIM 是防止明显退化的辅助检查，**不等于艺术验收，也不保证任何像素完全相同**；原 WebP 全部保留。
