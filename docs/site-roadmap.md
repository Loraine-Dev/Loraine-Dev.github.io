## 设计与工程取舍

保持现有轻量静态工程和 GitHub Pages 兼容，不为了六个页面引入新框架。由构建脚本生成 `/works/index.html` 等标准静态路由；内页不加载首页绘景、云层或 Three。共享导航、页脚、品牌符号与 CSS 变量，保持键盘操作、活动导航、跳过链接和减少动态支持。

首页负责空间和奇观；内页以深墨色或柔和浅纸色、节制的金/冰蓝标记、中文行长和中英字号层级构成艺术画册。每页使用自己的留白与节奏，不复用首页大背景，也不堆卡片。

- `src/data/site.json`：品牌、链接、公共文案；本轮已纠正作品状态。
- 作品数据未来独立为数组：`slug/title/status/genre/plannedPlatforms/description/conceptAssets`。`status=planning`，不能自动显示试玩或下载。
- 创作记录未来由 `content/journal/` 的真实内容文件生成；front matter 包含 slug、标题、真实日期与摘要；当前集合为空。
- `src/components/` 共享静态片段、`src/pages/` 页面模板、`src/styles/` 统一变量与布局。标题、描述、canonical、OG 与站点地图由页面数据生成。
- 场景代码与内容构建解耦；动画参数、素材生成器与来源清单独立。新增作品不必修改场景。
- 先本地构建/响应式/无 JS/链接与可访问性检查，再建立 PR。正式站只有用户确认后才发布；上线前按实际部署路径校验资源及路由。

此路线没有授权当前跳过首页验收实施整站，也不意味着生产部署已经完成。
